This repository contains the complete work I produced for Assignment 1 and Assignment 2 in the course COSC 8312, Introduction to Linux. All tasks were carried out on an Ubuntu Linux system, and the work includes both the commands I used as well as screenshots demonstrating each operation. The goal of both assignments was to help me develop practical proficiency with the Linux command line environment while also improving my understanding of how Linux systems behave, how file systems are organized, and how professional system administrators manage files, users, permissions, logs, and security-related operations.

The first assignment focused on fundamental skills such as navigating through directories, distinguishing between absolute and relative paths, copying files, interpreting color conventions used by the terminal, and understanding how Linux organizes user-based directory structures. Through these exercises, I strengthened my ability to reason about directory paths without relying on trial-and-error. This helped me visualize directory hierarchies more clearly and understand why Linux uses different color codes for directories, executable files, and regular files. Completing the assignment also taught me the importance of understanding relative path depth, because incorrect relative paths often lead to errors such as “cp: cannot stat,” which I encountered and resolved by verifying the actual directory location using commands such as pwd, ls .., and absolute paths. By the end of the first assignment, I was confident in moving through the Linux file system, listing directory contents, creating structured file paths, and manipulating files efficiently.

The second assignment expanded significantly on these basics and introduced more advanced Linux concepts. It began with an investigation of key system directories such as /bin, /etc, /var, /usr, /tmp, and others, requiring me to reason about which directories an attacker is most likely to target. I learned why configuration files in /etc represent a critical attack surface, why essential binaries in /bin and /usr/bin are valuable targets for replacement attacks, and why the /var/log directory often contains traces of unauthorized access. This exercise served as an introduction to Linux forensics and helped me understand how system administrators evaluate the integrity of a compromised system.

After the forensic analysis, I created and manipulated large directory structures using efficient commands such as brace expansion. For instance, I generated nested project directories, web project skeletons with multiple HTML, CSS, and JavaScript files, and backup files with specific naming conventions. This helped me appreciate the power of shell automation and how administrators avoid repetitive manual labor by using patterns and expansions. I also completed a navigation challenge that forced me to move across complex directory paths using as few cd commands as possible, without relying on absolute paths. This reinforced my ability to track directory depth internally and maintain awareness of my current working directory, which I verified at every step using pwd.

One of the more interesting tasks involved manipulating files using wildcards. I used shell patterns to move files that ended with digits, copy CSS files while excluding certain patterns, identify files with exactly three characters before their extension, detect files beginning with consonants, and filter files based on the length of their extension. This part of the assignment improved my understanding of pattern-matching and how wildcards differ from regular expressions. It also highlighted how powerful these tools are when cleaning large directories.

I then worked with brace expansion to generate hundreds of files in only a few keystrokes. I created daily log files for the first quarter of 2024, configuration files for multiple environments across different services, and test files combining letters, numbers, and suffixes. This demonstrated the efficiency of shell expansions in automating repetitive tasks and generating highly structured datasets.

The assignment also required comparing Linux and Windows line endings. I generated two identical text files, one using LF and the other using CRLF, and compared them using tools like diff, cmp, and comm. This demonstrated how line endings, despite being invisible, affect file comparison results and cross-platform compatibility. This gave me practical insight into problems that developers face when transferring files between different systems.

Another major component involved the use of the find command for forensic and administrative purposes. I created a directory with a variety of files and then used find to detect files larger than the directory’s average size, locate files modified within specific time ranges, identify empty or near-empty directories, detect world-writable files, and search for files owned by other users. By combining conditions such as -mtime, -size, -perm, and regex filters, I learned how powerful and flexible the find command is when locating and analyzing system files.

I also created a large log file containing more than two hundred lines and practiced extracting portions of it. I retrieved the middle fifty lines using sed, found the last occurrence of a specific word with a five-line context window, compared loading times between tools such as cat, less, and grep, and demonstrated why less is far superior for handling large files over slow network connections such as SSH sessions.

Automation with find -exec followed, where I changed permissions for files while preserving executable permissions, calculated total disk usage for older files, created backup versions of all configuration files, and safely removed temporary files using interactive execution modes that preview potentially destructive operations. This taught me how Unix systems balance power with safety, and why careful execution is crucial when running recursive operations.

I then created directories with different types of files and compared compression tools such as gzip, bzip2, xz, and zip. I discovered that already-compressed files like JPEGs and MP4s benefit very little from recompression, while text-heavy directories show significant improvements with tools like xz at the cost of speed. Through timing and comparing compression ratios, I formed informed conclusions about which formats are ideal for automated backups.

Archive management was another important part of the assignment. I worked with .tar, .gz, .bz2, .xz, and .zip formats and learned how to inspect archive contents without extracting them, selectively extract specific file patterns, update an existing archive, and handle corrupted archives safely. I also created a scenario requiring me to merge multiple archives into one, which taught me how to unify collections of files regardless of their original format.

Backup rotation was another key task. I designed a comprehensive system including daily incremental backups, weekly full backups, and monthly archives. I included metadata preservation such as permissions and timestamps, implemented integrity checks, and adopted a naming structure that prevents accidental overwrites and supports efficient restoration.

The final sections of the assignment involved user and group analysis as well as sudo forensics. I compared my user’s groups with another user, examined the /etc/passwd file to differentiate between system accounts and regular accounts, and explored the consequences of assigning overly broad permissions to normal users. I demonstrated how group changes take effect only after re-authentication and identified which groups grant access to sensitive system files. I then analyzed my sudo privileges, compared different privilege escalation methods such as sudo -i, sudo su, and su -, and examined system logs to identify patterns of privileged access. This exercise showed me how misconfigured sudo policies can expose a system to serious security risks.

I concluded the assignment by building a forensic analysis environment containing multiple file types, symbolic and hard links, device files, archives, and files with special permission bits such as setuid, setgid, and the sticky bit. I described how an investigator would interpret these artifacts and how certain irregularities may indicate intrusion attempts or unauthorized access.

Through these assignments, I gained a deep and practical understanding of Linux’s file system, security model, permission architecture, and administrative tools. I learned how to automate complex tasks, analyze system behavior, investigate security incidents, and maintain organized project structures. More importantly, the assignments strengthened my ability to think critically when interacting with the Linux terminal, diagnose errors, and build efficient workflows that reflect professional system administration practices. All screenshots and demonstration materials have been included in the repository to validate the execution of every command used throughout the project.
